# 10구단 체제 (1단계 — 게임 엔진 · 2단계 — 화면·문구)

새 게임은 10구단·81경기, 기존 세이브는 8구단·84경기로 그대로 이어진다. 이 문서는 엔진 작업의 결정·사용법·검증 수치와, 다음 워커(화면·문구·난이도 재조정)에게 넘기는 일을 적는다.

### 지시와 다르게 된 것 (확인 필요)

- **상대별 홈/원정은 5:4 가 아니라 6:3 또는 3:6 이다.** 상대당 9경기를 3연전 3번으로 치르고 3연전은 한 구장에서 이어지므로, 홈 3연전이 2번(6경기) 아니면 1번(3경기)이다. 5:4 는 3연전을 쪼개야만 가능해서 "3연전 구조 유지 · 유저 홈 42"를 우선했다.
- 와일드카드 탈락을 기록하려고 `PostFinish` 에도 `'WC'` 를 넣었다(`PostRound` 와 함께 유니온 확장). WC 에서 진 시즌도 "가을야구 진출"(`post !== 'none'`)로 센다. 새로 정한 값: 배당 `POST_DIVIDEND.WC` 1.5억, `POST_LEVEL.WC` 1(= 준PO 와 같은 "진출" 단계), `POST_CONSOLE.WC` 3, `RENEW_PREMIUM.WC` 0.02, 관중 수요 배율 1.2 — 전부 임시값, 난이도 워커가 확정.

### 와일드카드 결정전 규칙 (엔진)

4위(hi) vs 5위(lo), 전 경기 4위 홈. `PostSeries.hiW` 가 **1에서 시작**한다(`bestOf: 3`, 2승 선취). 이 라운드만 무승부가 있고(연장 재시뮬 없음) 비기면 그 자리에서 4위 통과. 5위는 2연승해야 통과, 최대 2경기. 경기 번호는 `s.games.length` 로 센다(`hiW + loW` 가 아님). 유저 화면에 보이는 "시리즈 n승 m패"(`DayReport.post.myW/oppW`)에는 안고 시작한 1승이 포함된다.

## 2. 헬퍼 사용법 (`src/game/league.ts`)

| 헬퍼 | 뜻 | 8구단 | 10구단 |
|---|---|---|---|
| `leagueSize(core)` | 구단 수 | 8 | 10 |
| `seasonGames(core)` | 시즌 경기 수 (일정이 비면 구단 수에서 유도) | 84 | 81 |
| `dayAt(core, n)` | 84경기 기준 n경기째 → 이 리그의 경기일 (반올림) | n | round(n × 81/84) |
| `blockDayAt(core, n)` | 위와 같되 3연전 경계에 맞춤 (6연전 구간 시작) | n | 예: 48 → 45, 78 → 75 |
| `perLeague(core, n)` | 8구단 기준 개수 → 구단 수 비례 | n | round(n × 10/8) |
| `postTeams(core)` / `postRounds(core)` | 포스트시즌 팀 수 / 라운드 순서 | 4 / SPO·PO·KS | 5 / WC·SPO·PO·KS |
| `inPost(core, rank)` | 가을야구 진출권 순위인가 | ≤ 4 | ≤ 5 |
| `isLast(core, rank)` | 꼴찌인가 | 8 | 10 |
| `perGame(core, v)` | 84경기 기준 경기당 금액 → 시즌 합계가 같은 경기당 금액 | v | v × 84/81 |
| `rankUnits(core, rank)` | 순위 몫 단위 (꼴찌 0 ~ 1위 7) | 8 − rank | (10 − rank) × 7/9 |

파생 헬퍼: `tradeDeadline(core)`·`regDeadline(core)`(economy.ts), `trFrom(core)`·`trTo(core)`(trade.ts), `midDay(core)`(script.ts), `draftPool(core)`(draft.ts), `buildPost(core)`(postseason.ts — 대진표 미리보기도 이것을 쓴다), `teamDefs(n)`(generate.ts).

**새 코드 규칙**: 8·7·84·72 같은 숫자를 박지 말고 위 헬퍼를 쓴다. 상수 `TRADE_DEADLINE`(54)·`REG_DEADLINE`(72)·`MID_DAY`(42)·`TR.from/to`·`F.armyDay` 등은 "84경기 기준값"으로 남아 있으니 직접 비교에 쓰지 않는다.

- **순위표**(리그 탭 · 결산): 가을야구 막차 순위(`postTeams`) 아래 초록 선, 와일드카드 자리 숫자는 하늘색, 표 아래 범례 한 줄. 360×640 에서 10줄 + 범례가 한 화면에 든다.

## 5단계(빚내는 플레이) — 경쟁균형세 · 빚더미 구단 여론

문제: 10구단에서 "빚을 한도까지 당겨 스타 FA 를 쓸어 담는" 플레이(greedy 봇)가 벌 없이 통했다(우승 12/12 · 중앙 4시즌 · 연고 이전 8% · 도민 지지 90대).
해법은 유저가 고른 둘만 넣었다: **B 경쟁균형세**, **C 빚더미 구단에 대한 도민 여론**. FA 영입 인원 한도·대출 한도 축소·이자 인상은 하지 않았다. 전부 10구단 리그(구단 수 > 8)에서만 적용되고 8구단 세이브는 수정 전과 같다.

### 5-1. 확정한 규칙

이유:
- **유저를 뺀 상위 3구단**: 유저가 상위 3에 들면 자기 연봉이 상한을 끌어올린다(greedy 4시즌째 연봉 133억이면 상한이 +17억).
- **AI 연봉 분포**(sensible 런 평균, 억 · 1위/3위/5위/9위 · 유저 뺀 상위 3 평균): 1시즌 86/68/55/33 · **76** → 3시즌 100/76/64/39 · 87 → 6시즌 109/81/72/47 · **93**(정점) → 9시즌 103/77/70/52 · 88 → 12시즌 85/70/63/50 · **78**. AI 연봉은 6시즌 뒤로 줄어든다(유저 왕조가 스타를 가져간다). 상한을 그때그때의 AI 연봉에만 묶으면 왕조기에 상한이 105억 → 92억으로 내려가 sensible 이 9~12시즌에 시즌당 11~28억을 냈다. 그래서 상한에 바닥(내려가지 않음 + 연봉 인상률)을 두었다.

- **80% · −5/−10 · 유예 1**: greedy 는 3시즌째부터 부채가 한도의 94~97% 로 붙는다(한도가 매출을 따라 올라도 5억 단위로 끝까지 빌린다) → 3시즌째 경고, 4시즌째부터 매 시즌 −5~−10. 24시드로 잰 감소폭별 greedy 이전율: −3/−6 13% · −4/−8 13% · −5/−10 29% · −6/−12 33% · −7/−14 54% (상한 × 1.15 · 인상률 바닥을 넣기 전), 확정한 상한에서는 **−5/−10 33%** · −6/−12 38%. sensible 은 12시즌 144시즌 중 빚더미 결산이 4시즌(왕조기 1~2런)뿐이고 지지 감소는 0.

## 6단계(FA 계약금 누진) — 같은 시즌에 FA 를 영입할수록 계약금이 오른다

"빚을 한도까지 당겨 스타 FA 를 쓸어 담는" 플레이(greedy)의 우승 속도를 **인원이 아니라 값으로** 누른다(유저 제안). 10구단 리그에만 적용, 8구단 옛 세이브는 그대로.

### 6-0. 구단 이름 (같이 한 일)

"용인 판다스"(`YIN`) → **"한강 판다스"(`HAN`)**. 옛 세이브의 "한강 그리폰즈"와 id 가 같아져 `LEGACY_TEAM_ID` 매핑을 지웠다. `npm run oldsave` 크래시 0 · 위반 0.

**주의 — 이름만 바꿨는데 봇 지표가 움직인다.** 순위 동률은 구단 id 순으로 가른다(`season.ts` standings). `YIN` 은 `JEJ` 뒤, `HAN` 은 `JEJ` 앞이라 같은 시드의 시즌 전개가 달라진다. 엔진 변경(6단계) 없이 id 만 바꿔도 `TEAMS=8 … 6 8 0 0` 출력이 달라지고(id 를 `YIN` 으로 되돌리면 수정 전과 한 글자도 다르지 않다 — 6단계 엔진이 8구단에 영향이 없다는 확인은 이것으로 했다), 10구단 24시드의 greedy 연고 이전도 5단계 문서의 33% 에서 63% 로 달라졌다. 즉 **24시드의 이전율은 ±15%p 안팎으로 흔들리는 값**이다. 아래 "수정 전"은 전부 `HAN` 으로 다시 잰 값이다.

### 6-1. 확정한 규칙

| 항목 | 값 |

| 배율 `FA_HEAT.mult` | n=0 ×1.0 · n=1 ×1.5 · n=2 ×2.5 · n=3 ×4 · n=4 ×6 · 그 뒤 한 명마다 +2 |

영입 선수의 연봉 × (1 + k·n)(이번 측정에서는 첫 시즌만이 아니라 계약 내내), 확정 배율과 함께, greedy 24시드.

| k | 우승 · 중앙 | 연고 이전 | 평균 연봉 |
|---|---|---|---|
| 0 (확정) | 15/24 · 4.0 | 67% | 94억 |
| 0.1 | 18/24 · 4.5 | 58% | 99.3억 |
| 0.2 | 6/24 · 4.0 | 83% | 90.3억 |

k=0.1 은 우승을 반 시즌 더 늦추지만 6시즌에는 못 닿고, k=0.2 는 늦추는 것이 아니라 망하게 한다(우승 6/24 · 이전 83%). `FA_HEAT.pay`(게임에서는 0)와 `FAHEATPAY` 로 다시 잴 수 있다.

### 6-9. 못 한 것 · 확인 못 한 것

- **greedy 우승 중앙 6시즌 이상은 못 맞췄다**(12시드 5.5 · 24시드 4.0). 계약금만으로는 한계가 있다.
- **greedy 연고 이전은 목표(25~40%) 밖**(67%). 구단 id 변경으로 기준 자체가 63~75% 로 올라가 있었고, 빚더미 감소폭·배율을 낮춰 맞추는 측정은 시간이 없어 못 했다. 24시드로도 ±15%p 흔들리므로 맞추려면 시드를 늘려야 한다.
